# Entity ID Manager

Отдельные части `entity_id` для зон, устройств и сущностей в Home Assistant. Названия комнат, устройств и объектов в интерфейсе остаются прежними.

Например: зона **Ванная** → `bathroom`, устройство **Нептун** → `neptun`, датчик **Протечка** → `water_leak`. Результат: `binary_sensor.bathroom_neptun_water_leak`.

## Установка через HACS

1. В HACS откройте меню → Пользовательские репозитории.
2. Добавьте `https://github.com/Odysseos/ha_entity_id_manager`, категория **Интеграция**.
3. Установите Entity ID Manager и перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Entity ID Manager**.

Требуется Home Assistant 2026.10 или новее. Интеграция настраивается через интерфейс; YAML не требуется.

## Настройка

Откройте **Entity ID Manager** в боковом меню HA и нажмите **Открыть редактор**. Редактор доступен администраторам. Ссылка на него также есть в настройках интеграции → **Редактор соответствий**.

1. Выберите вкладку **Зоны**, нужную зону и введите её часть ID во второй строке, например `bathroom`.
2. Переключитесь на другую зону или вкладку: введённое значение останется в черновике. На вкладке **Устройства** задайте, например, `neptun`, на вкладке **Сущности** — `water_leak`.
3. В списке сохранённая часть показана на нейтральном фоне. При изменении старое значение зачёркивается на красном фоне, а черновое показывается рядом на зелёном. При первом назначении показана только зелёная плашка. Подписей на плашках нет. Список поддерживает поиск по названию и обеим частям ID.
4. **Очистить** удаляет значение выбранного объекта в черновике: остаётся только старое значение, зачёркнутое на красном фоне.
5. **Сбросить изменения** возвращает выбранному объекту сохранённое значение. Черновики остальных объектов сохраняются.
6. **Подтвердить** сохраняет все изменённые соответствия на всех вкладках одной операцией. Неверное значение блокирует подтверждение.
7. **Отмена**, крестик, Escape или закрытие редактора сбрасывают весь несохранённый черновик. Черновик не сохраняется при уходе со страницы или её перезагрузке.
8. Для переименования самих сущностей откройте **Настройки → Устройства и службы → Entity ID Manager → Просмотр и применение**, отметьте нужные изменения и подтвердите.

Если соответствия изменены из другого окна или через текстовую сущность, редактор не перезапишет их старым черновиком. Отмените его и откройте редактор заново, чтобы загрузить актуальные значения.

Настроенные объекты идут первыми в списках. При возвращении к сохранённому значению остаётся одна нейтральная плашка.

Сохранённые соответствия также появляются как редактируемые текстовые сущности под интеграцией: **Настройки → Устройства и службы → Entity ID Manager → Объекты**. Откройте нужную запись, чтобы изменить её значение. Изменения сразу сохраняются; для переименования исходных сущностей используйте **Просмотр и применение**. Текстовые сущности настроек не участвуют в переименовании.

При очистке значения соответствие удаляется. Его текстовая сущность остаётся пустой, чтобы значение можно было задать снова. После перезагрузки интеграции записи без соответствия не загружаются.

Сохранение отдельной части не переименовывает существующие сущности. Пустое значение удаляет переопределение. Это не возвращает уже изменённые ID.

Допустимы строчные латинские буквы, цифры и подчёркивания; первый символ — буква. Домен (`sensor`, `switch` и т. п.) сохраняется.

## Правила формирования ID

Формат: `<domain>.<area>_<device>_<suffix>`.

- Зона берётся из назначения самой сущности, иначе из назначения устройства. Часть зоны добавляется только при наличии её переопределения.
- Часть устройства берётся из переопределения; иначе из текущего названия устройства с нормализацией HA.
- Суффикс берётся из переопределения. Иначе используется исходное имя сущности от интеграции; для основной сущности без имени — `state`. Для старых интеграций без исходного имени исходная часть ID после точки сохраняется отдельно и используется повторно, чтобы префиксы не накапливались.
- Обрабатываются только сущности с переопределением зоны, устройства или собственного суффикса. Для полностью независимого от русских названий ID задайте все нужные части явно.
- Привязки хранятся по стабильным ID реестров, поэтому изменение `entity_id` не теряет настройку суффикса.

Занятые и повторяющиеся целевые ID показываются как конфликты и не доступны для выбора. Обмен ID между двумя сущностями за одну операцию не выполняется. Перед применением весь выбранный список проверяется повторно. При ошибке интеграция пытается вернуть уже изменённые ID и сообщает об ошибке.

## Автоматический режим

По умолчанию выключен. Обрабатывает только появление новых записей реестра с уже настроенными частями. Изменение зоны, названия устройства или настроек частей само по себе не запускает массовое переименование. Для существующих сущностей используйте просмотр и применение. Конфликтующие новые сущности пропускаются.

## Ссылки на сущности

Интеграция меняет реестр сущностей через API Home Assistant. Она не переписывает автоматизации, панели, шаблоны или файлы конфигурации. Перед применением список изменений содержит старые и новые ID. Обновите ссылки в собственной конфигурации, в том числе фильтры и `entity_config` YaHA. В УДЯ изменение ID может означать появление нового устройства.

Переименования не изменяют команды физического устройства, его настройки, `unique_id`, зоны или отображаемые названия. Штатная команда HA «Пересоздать идентификаторы» использует правила HA и не учитывает настройки Entity ID Manager.
