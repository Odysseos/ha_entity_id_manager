# Entity ID Manager

Отдельные сегменты `entity_id` для зон, устройств и сущностей в Home Assistant. Названия комнат, устройств и объектов в интерфейсе остаются прежними.

Например: зона **Ванная** → `bathroom`, устройство **Нептун** → `neptun`, датчик **Протечка** → `water_leak`. Результат: `binary_sensor.bathroom_neptun_water_leak`.

## Установка через HACS

1. В HACS откройте меню → Пользовательские репозитории.
2. Добавьте `https://github.com/Odysseos/ha_entity_id_manager`, категория **Интеграция**.
3. Установите Entity ID Manager и перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Entity ID Manager**.

Требуется Home Assistant 2026.10 или новее. Интеграция настраивается через интерфейс; YAML не требуется.

## Настройка

Нажмите шестерёнку **Entity ID Manager** на странице интеграций: редактор откроется сразу. Редактор доступен администраторам. Через боковое меню **Entity ID Manager** открывается страница управления с кнопками редактора, предпросмотра и настройкой автоматического режима.

1. В дереве слева выберите зону и введите её сегмент ID в редакторе справа, например `bathroom`. Стрелка раскрывает ветку, нажатие на название выбирает объект.
2. Раскройте зону, выберите устройство и задайте, например, `neptun`; выберите его сущность и задайте `water_leak`. При переходах между любыми объектами значения остаются в черновике.
3. В списке сохранённый сегмент показан на нейтральном фоне. При изменении старое значение зачёркивается на красном фоне, а черновое показывается рядом на зелёном. При первом назначении показана только зелёная плашка. Подписей на плашках нет. Список поддерживает поиск по названию и обоим сегментам ID. Дерево прокручивается под закреплённым полем поиска. Модель содержит все объекты и обновляется сразу; визуальный контрол создаёт строки только в видимой области. Изменения скрытых или находящихся за пределами экрана объектов сохраняются в черновике и отображаются при раскрытии или прокрутке. Поиск раскрывает подходящие ветки и сохраняет родителей для контекста.
4. **Очистить** удаляет значение выбранного объекта в черновике: остаётся только старое значение, зачёркнутое на красном фоне.
5. **Сбросить изменения** возвращает выбранному объекту сохранённое значение. Черновики остальных объектов сохраняются.
6. **Подтвердить** сохраняет все изменённые соответствия во всём дереве одной операцией. Неверное значение блокирует подтверждение.
7. **Отмена**, крестик, Escape или закрытие редактора сбрасывают весь несохранённый черновик. Черновик не сохраняется при уходе со страницы или её перезагрузке.
8. Для переименования самих сущностей закройте редактор и нажмите **Просмотр и применение** на странице Entity ID Manager. Отметьте нужные изменения и нажмите **Применить выбранные**. Конфликтующие строки недоступны для выбора.

Если соответствия изменены из другого окна или через текстовую сущность, редактор не перезапишет их старым черновиком. Отмените его и откройте редактор заново, чтобы загрузить актуальные значения.

В дереве у каждой строки есть иконка. Иерархия: зона → устройство → сущности. В строках показаны собственные названия, полный путь — у выбранного объекта справа. Если назначения нет, отображается «Без зоны» или «Без устройства». Для сущности учитывается её собственная зона, иначе зона устройства. Под названием устройства мелким шрифтом показаны модель и производитель, под названием сущности — исходное название параметра из HA. В подписи также указана интеграция. Эти сведения доступны в поиске. Перед частью ID устройства показана сегмент ID зоны, перед частью ID сущности — сегменты ID зоны и устройства. Общий префикс выделен бледно-жёлтым и учитывает текущие черновики родителей; незаданные сегменты показаны как `<area_id>` и `<device_id>`. В родительском префиксе сохранённые сегменты жёлтые, а черновые изменения — зелёные. При удалении сегменты её место занимает зелёный `<area_id>` или `<device_id>`. Старые красные значения родителей в префиксе не дублируются. Исходный `entity_id` доступен во всплывающей подсказке и поиске.

Устройства и сущности без зоны всегда идут последними; для списков используется общая сортировка. Сначала внутри зоны показаны устройства, затем сущности без устройства. Объекты сортируются по собственным названиям. Каждый уровень сравнивается отдельно, поэтому разделители пути не влияют на порядок. Сохранённые сегменты ID и черновики не влияют на порядок. Рядом с каждой строкой и выбранным объектом есть ссылка на карточку HA: зоны, устройства или сущности. Ссылка открывается в новой вкладке и поддерживает стандартное контекстное меню браузера; черновик редактора сохраняется. При возвращении к сохранённому значению остаётся одна нейтральная плашка.

Сохранённые соответствия также появляются как редактируемые текстовые сущности под интеграцией: **Настройки → Устройства и службы → Entity ID Manager → Объекты**. Откройте нужную запись, чтобы изменить её значение. Изменения сразу сохраняются; для переименования исходных сущностей используйте **Просмотр и применение**. Текстовые сущности настроек не участвуют в переименовании.

При очистке значения соответствие удаляется. Его текстовая сущность остаётся пустой, чтобы значение можно было задать снова. После перезагрузки интеграции записи без соответствия не загружаются.

Сохранение отдельного сегмента не переименовывает существующие сущности. Пустое значение удаляет переопределение. Это не возвращает уже изменённые ID.

Допустимы строчные латинские буквы, цифры и подчёркивания; первый символ — буква. Домен (`sensor`, `switch` и т. п.) сохраняется.

Окно редактора сохраняет размер и положение при выборе объектов. Блок выбранного объекта имеет постоянную высоту, поле ID и нижние кнопки остаются на своих местах. Подробности и длинные сообщения прокручиваются в отдельной средней области.

В редакторе проверяется полный будущий `entity_id` с учётом всех черновиков и подстановок. У сущности красный значок рядом с ID отмечает конфликт. У зон и устройств показан значок с числом конфликтующих дочерних сущностей; нажатие фильтрует дерево по конфликтующим сущностям соответствующей зоны или устройства, сохраняя их родителей. Подробности отображаются только для выбранной сущности: первые три совпадения, затем кнопка «Ещё N». Полный список раскрывается в блоке с прокруткой. Над выбором объекта расположены кнопки фильтра: «Все объекты», «Все конфликты (N)» и, после перехода от родителя, отдельная кнопка выбранной зоны или устройства со своим числом конфликтующих сущностей. Между общим и родительским фильтром можно переключаться одним нажатием. Соответствия можно сохранить даже с конфликтами; конфликтующие переименования применить нельзя. Если проверка недоступна, редактор показывает сообщение об этом, а не нулевой счётчик.

У сущности третьей строкой показан текущий полный `entity_id`. Кнопка «Скопировать текущий ID» копирует его в буфер обмена. Это действующий ID в HA, а не результат черновика. У зон и устройств собственного `entity_id` нет.

На узком экране дерево расположено над редактором. Сущности без устройства находятся непосредственно в своей зоне, а объекты без зоны — в отдельной невыбираемой группе в конце. Если сущности назначена собственная зона, отличающаяся от зоны устройства, ветка устройства также показана в этой зоне для доступа к её сущностям. Обе строки устройства редактируют одно соответствие.

## Сущность без собственного сегмента ID

Для сущностей доступен переключатель «Без собственного сегмента ID». При его включении ID собирается только из домена, зоны и устройства: например, `binary_sensor.bathroom_lamp`. Пустое поле при выключенном переключателе по-прежнему означает подстановку по умолчанию.

Поле остаётся доступным. Установка курсора не меняет режим, а ввод или вставка текста автоматически отключает переключатель. Если выключить переключатель вручную, возвращается значение, введённое до его включения в текущем редакторе. «Очистить» отключает режим и возвращает подстановку по умолчанию; «Сбросить изменения» восстанавливает сохранённое состояние. Изменения применяются и отменяются вместе с остальными черновиками.

В дереве режим показан плашкой «Без сегмента», в редакторе виден итоговый ID. Его можно скопировать одноимённым сущностям обычной групповой операцией. Домены входят в полный ID: `binary_sensor.bathroom_lamp` и `switch.bathroom_lamp` различны. Если полный ID совпадает с другой сущностью или после исключения собственного сегмента не остаётся ни одного сегмента, проверка блокирует применение.

Для основной сущности устройства редактор может предложить «Убрать собственный сегмент». Признак — интеграция пометила сущность через `has_entity_name`, но не задала ей собственного `original_name`. Предложение появляется только при свободном итоговом ID с учётом черновиков. Сохранённый собственный сегмент не заменяется. Нажатие включает режим в черновике; сохраняется он только общей кнопкой «Подтвердить». Автоматически режим не включается.

## Копирование сегмента ID одноимённым объектам

При выборе устройства или сущности кнопка «Для одноимённых (N)» копирует введённый сегмент ID другим объектам с таким же собственным названием. Зона и название родительского устройства при сравнении не учитываются; регистр букв и пробелы по краям также не учитываются. Например, `humidity` можно назначить всем сущностям «Влажность» из разных комнат. Число N показывает количество остальных одноимённых объектов, у которых значение действительно изменится. Совпадающие значения, включая черновики, не учитываются. Объекты с уже правильным полным `entity_id` также исключаются, даже если сегмент ID для них не сохранялся в редакторе. Для устройства проверяются итоговые ID его сущностей с учётом текущих черновиков. Для вариантов «Только незаданные» и «Заменить у всех» показываются отдельные счётчики; вариант без изменений недоступен.

Если у найденных объектов уже есть другие значения, выберите «Только незаданные» или «Заменить у всех». Учитываются и сохранённые значения, и текущие черновики. Одинаковые значения пропускаются. Пустое или некорректное значение копировать нельзя.

Групповая операция меняет только черновики; «Подтвердить» сохраняет их вместе. Результат последней групповой операции и её кнопка «Отменить» показываются только у объекта, из которого она была запущена. При переходе к другому объекту они скрываются, при возвращении — появляются. «Отменить» рядом с результатом отменяет последнюю групповую операцию, сохраняя последующие ручные изменения. Общая отмена редактора сбрасывает все черновики. Конфликты пересчитываются автоматически. Это разовое копирование: новые одноимённые объекты не наследуют соответствие.

## Правила формирования ID

Формат: `<domain>.<area>_<device>_<suffix>`.

- Зона берётся из назначения самой сущности, иначе из назначения устройства. Сегмент зоны берётся из переопределения; если оно не задано — из названия зоны с транслитерацией и нормализацией HA. Если зона не назначена, сегмент пропускается.
- Сегмент устройства берётся из переопределения; иначе из текущего названия устройства с нормализацией HA.
- При режиме «Без собственного сегмента ID» суффикс пропускается. В остальных случаях суффикс берётся из переопределения. Иначе используется исходное имя сущности от интеграции; для основной сущности без имени — `state`. Для старых интеграций без исходного имени исходный сегмент ID после точки сохраняется отдельно и используется повторно, чтобы префиксы не накапливались.
- Обрабатываются только сущности с переопределением зоны, устройства или собственного суффикса. Для полностью независимого от русских названий ID задайте все нужные сегменты явно.
- Привязки хранятся по стабильным ID реестров, поэтому изменение `entity_id` не теряет настройку суффикса.

Занятые и повторяющиеся целевые ID показываются как конфликты и не доступны для выбора. Обмен ID между двумя сущностями за одну операцию не выполняется. Перед применением весь выбранный список проверяется повторно. При ошибке интеграция пытается вернуть уже изменённые ID и сообщает об ошибке.

## Автоматический режим

Переключатель находится на странице Entity ID Manager. По умолчанию выключен. Обрабатывает только появление новых записей реестра с уже настроенными сегментами. Изменение зоны, названия устройства или настроек сегментов само по себе не запускает массовое переименование. Для существующих сущностей используйте просмотр и применение. Конфликтующие новые сущности пропускаются.

## Ссылки на сущности

При применении переименований интеграция обновляет ссылки в подключённых YAML-файлах, автоматизациях, скриптах, шаблонах, панелях и настройках интеграций. Это включает фильтры и `entity_config` YaHA. Перед записью создаётся резервная копия; при ошибке выполняется откат. Подробности, расположение копий и ограничения описаны в [обновлении ссылок](docs/reference_updates.md).

Переименования не изменяют команды физического устройства, его настройки, `unique_id`, зоны или отображаемые названия. Штатная команда HA «Пересоздать идентификаторы» использует правила HA и не учитывает настройки Entity ID Manager.
