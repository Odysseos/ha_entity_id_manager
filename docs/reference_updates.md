# Обновление ссылок при переименовании

Обновление выполняется при применении списка переименований, а также при автоматическом переименовании новых сущностей. Сохранение частей ID в редакторе само по себе конфигурацию не переписывает.

Например, при переименовании `sensor.multi_bathroom_humidity` в `sensor.bathroom_multisensor_humidity` обновятся и обычные ссылки, и ссылки внутри шаблонов:

```yaml
entity_id: sensor.bathroom_multisensor_humidity
value_template: "{{ states('sensor.bathroom_multisensor_humidity') | float(0) }}"
```

## Где обновляются ссылки

| Источник | Что обрабатывается |
| --- | --- |
| YAML | `configuration.yaml` и доступные из него `!include`, `!include_dir_list`, `!include_dir_named`, `!include_dir_merge_list`, `!include_dir_merge_named`; вложенные подключения и packages |
| Автоматизации, скрипты, сцены, группы, шаблоны | Полные ID в параметрах, списках, ключах словарей и строках Jinja; используемые blueprint-файлы |
| Пользовательские Jinja-шаблоны | Файлы `custom_templates/**/*.jinja` |
| Панели | Загруженные панели Lovelace в режиме хранения и YAML, включая подключённые файлы |
| Настройки интеграций | `data`, `options` и данные подзаписей, сохранённые через config entries; в том числе настройки помощников |
| Зоны | Выбранные датчики температуры и влажности |
| Пользователи | Списки трекеров присутствия у пользователей, созданных через интерфейс |
| Энергия | Ссылки в настройках панели энергии |
| YaHA | YAML-фильтры, `entity_config` и шаблоны, если их файлы входят в активную конфигурацию HA |
| Секреты | Значения в `secrets.yaml`, целиком совпадающие с переименованным ID; имена секретов сохраняются |

Изменение файлов сохраняет комментарии, отступы, кавычки и окончания строк. Ссылки заменяются по полному ID: `sensor.example` не заменит часть `sensor.example_backup`. Замены в пакете выполняются одновременно, без повторной замены уже полученного результата.

`unique_id`, `default_entity_id`, идентификаторы устройств, MQTT-топики, пароли и токены сохраняются. Они не являются ссылками на текущий `entity_id`. Если YAML-якорь одновременно используется для ссылки и защищённого идентификатора, операция отклоняется: сначала нужно разделить эти значения в YAML.

## Применение и перезагрузка

1. Проверяются конфликты итоговых ID и актуальность списка переименований.
2. Подготавливаются замены и сохраняются оригиналы изменяемых данных.
3. Записываются файлы и запускается проверка конфигурации Home Assistant. При ошибке проверки переименование не выполняется, файлы восстанавливаются.
4. Меняются ID в реестре и ссылки в сохранённых настройках. Вызывается перезагрузка YAML через `homeassistant.reload_all`, обновляются панели и поддерживающие перезагрузку записи интеграций.
5. Обновляются ссылки зон, пользователей и панели энергии. В результате показываются число замен, путь резервной копии и компоненты, требующие перезапуска.

Если компонент не поддерживает перезагрузку, его конфигурация уже исправлена, но для применения нужен перезапуск HA. Некоторые интеграции, включая облачные, могут требовать дополнительного обновления списка устройств на своей стороне. В УДЯ новый ID может означать появление нового устройства.

При ошибке записи или перезагрузки интеграция пытается восстановить исходные ID, файлы и настройки. Черновики частей ID при этом не удаляются. Если данные одновременно изменены другим редактором, чужие правки не перезаписываются; ошибка содержит список невосстановленных элементов и путь резервной копии.

## Резервные копии

Для каждой операции создаётся каталог внутри конфигурационного каталога HA:

```text
.storage/entity_id_manager_backups/<идентификатор операции>/
```

В нём находятся `manifest.json` и исходные файлы `file-0`, `file-1`, … В манифесте указаны исходные пути, соответствия старых и новых ID, прежние настройки и состояние операции: `prepared`, `committed`, `rolled_back` или `rollback_failed`.

Копии могут содержать секреты из конфигурации. Права каталога — `0700`, файлов — `0600`. Копии автоматически не удаляются.

Для ручного восстановления файлов остановите HA, найдите нужную операцию по `renames` в `manifest.json` и скопируйте каждый `file-N` в путь, указанный у него в `files`. Настройки интеграций, панелей, зон и пользователей перечислены в соответствующих разделах манифеста; восстанавливайте их через интерфейс или API соответствующего компонента. Не заменяйте работающие файлы `.storage` вручную. После восстановления файлов запустите HA и проверьте конфигурацию. Полная системная резервная копия HA дополнительно сохраняет реестры и историю; каталог операции её не заменяет.

## Границы замены

Обрабатываются полные ID, записанные непосредственно в конфигурации. Выражение `states('sensor.example')` обновится; ID, вычисляемый как `'sensor.' ~ room ~ '_temperature'`, автоматически вывести из частей нельзя. Маски вроде `sensor.example*` не переписываются: они могут описывать несколько сущностей.

Не меняются архивные и не подключённые к конфигурации YAML-файлы, файлы за пределами каталога HA, внешние приложения и произвольные внутренние хранилища сторонних интеграций. Файлы внутри `.storage` не переписываются поиском и заменой: поддерживаемые настройки обновляются через API HA. Переименование здесь не является отдельной миграцией истории Recorder или произвольных внешних статистических ID.

При аварийном завершении процесса HA автоматический откат не гарантирован: сохранённые оригиналы остаются в каталоге операции.
